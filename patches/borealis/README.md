# The fixes to borealis (shared with PlayGuard)

`extern/borealis` is the upstream submodule (xfangfang/borealis, wiliwili
branch), left at an upstream commit. The fixes PlayShelf and PlayGuard need before
upstream has them are kept here as patches, applied in name order to the
submodule's files when CMake configures (`CMakeLists.txt`). A patch already
in place is left as it is; one that no longer applies stops the configure,
so a borealis bump cannot silently drop a fix. `git status` does not show
them (`.gitmodules`: `ignore = dirty`); `git -C extern/borealis diff` does.

To change one: edit the file in `extern/borealis`, then
`git -C extern/borealis diff > patches/borealis/NNNN-name.patch` (one fix
per patch) and `git -C extern/borealis checkout .` before configuring again.
Once upstream has a fix, the bump that brings it removes its patch.

| Patch | Why |
|---|---|
| `0001-i18n-look-strings-up-without-exceptions.patch` | `getRawStr` looked each string up in the current locale first, with a lookup that throws when it misses. In English (the default locale) the current one is empty, so every `getStr` / `_i18n` threw and caught an exception, and `operator[]` added a null to that locale each time. The empty locale is now skipped and the lookup is `at()` on a const catalogue. Desktop build, 20,000 strings: 45 ms → 7.5 ms in English, French unchanged (8 ms). |
| `0002-label-same-text-not-laid-out-again.patch` | `Label::setText` laid the whole screen out again (`invalidate()`) even when the text did not change, and the tabs that refresh themselves every 1 to 5 s set dozens of texts, most of them the same each time. The same text now returns at once. Desktop build, steady refreshes: the Overview 1.0 → 0.25 ms, the Play timer 2.1 → 0.13 ms, PIN 0.27 → 0.1 ms (with 0003). |
| `0003-view-same-size-not-laid-out-again.patch` | `View::setWidth` / `setHeight` did the same with an unchanged size (the Play timer's week chart sets its seven bars' heights on every refresh). The same size, as set before (in points, or automatic), now returns at once. |
| `0004-view-xml-attributes-registered-when-needed.patch` | Every `View` constructor registered 76 XML attribute handlers (`std::function` in string-keyed maps), even for views built in code that never read one: All games builds four views per game. They are registered the first time an XML attribute is applied or checked, without replacing a subclass's own handler for the same name. Desktop build, 200 views: a `Label` 3–6 → 0.6–0.9 ms, a `Box` 4–5 → 0.7 ms, an All games cover 25 → 10 ms. |
| `0005-notifications-styled-from-the-theme.patch` | A toast's look was fixed in code: the backdrop's black, white text, square corners, the stack against the screen's top-right corner. Its background, text colour, corner radius, the gap between two toasts and the stack's distance from the top and the right are now theme and style values (`brls/notification/background`, `…/text`, `…/corner_radius`, `…/spacing`, `…/margin_top`, `…/margin_right`), with defaults that keep borealis' look, so the Cadran appearance can draw its toasts as cards; and `Application::notify` takes an optional view to put before the text (an icon: a success, a refusal). |
| `0006-box-hidden-gives-no-focus.patch` | A hidden box (`GONE` or `INVISIBLE`) still handed the focus to a child left visible, though `isFocusable()` refuses a hidden view: hiding a row of chips, or a card holding a button, left that button reachable, the focus out of sight. `Box::getDefaultFocus` now returns nothing while the box is not visible. |
| `0007-label-font-scale.patch` | A label's size was the one asked, with no way to make every text bigger. `Label::setFontScale` (1 by default) draws every label that many times its size, but those that keep theirs (`setFontScaled(false)`); `getFontSize()` keeps giving the size asked, and the measuring follows. The scale may change at any time, the labels then laid out again (`ui/text_size.cpp` marks their nodes dirty). The Cadran appearance uses 1.25 for Preferences › Text size's larger text, on the TV by default. Where a row is full already, a label can grow less, `setFontScaleMax(max)` drawing it at most `max` times its size, and `setShrinkToFit(true)` draws a single line its box is too narrow for smaller again, down to the size asked, rather than cutting or wrapping it (the rail's tab names, the header's title, pill and date, `ui/cadran_frame.cpp`); `setHintsFontScaleMax(max)` does the same for the footer's hints and clock, which kept their size before (1 by default: they still do). At a scale of 1 nothing changes. |
| `0008-label-says-when-it-is-cut.patch` | A label cut short (drawn with "…") could not tell it was: `Label::isTruncated()` says so, for the desktop's check that no text of the 15 languages is cut (`source/ui/cut_text.cpp`, `tools/cut_text_check.py`). Nothing else changes. |
| `0009-highlight-still-on-request.patch` | The focus highlight's glow moves with the clock, two soft spots of its second colour along the frame; the smoke test gives that colour the stroke's own, but where they pass, the frame's anti-aliased edges come out darker, so the same screen differed from one run to the next by a few hundred pixels. `setHighlightAnimationStill(true)` holds them where they are (`PLAYGUARD_SIM_STILL_FOCUS`, `source/ui/theme.cpp`). |
| `0010-nbsp-keeps-words-together.patch` | nanovg broke a line at a no-break space (U+00A0) as at any space, so "PEGI 12" or "1 h 24" could end a line with "PEGI" or "1 h" and start the next with the number. A no-break space is now part of the word around it: the line breaks before or after the whole, never inside it. |
| `0011-wrapped-line-starts-after-the-space.patch` | borealis keeps the spaces in a line's measure (its cursor needs them), so a space also began the next word: a text wrapped at a space started its next line with it ("Dragon Valley" / " Legends", one space to the right). The word after a space now begins with its first letter, and the space where a line breaks is drawn on neither line. |
| `0012-i18n-load-another-language-while-running.patch` | The strings were loaded once, at start-up, in the platform's language. `loadTranslations(locale)` loads another language's in place of the current ones while the app runs, so Preferences › Language applies at once (`source/ui/live_prefs.cpp`, which builds the screens again). The platform's own locale is left as it is. |
| `0013-default-font-looked-up-each-time.patch` | Every label took the default font that the first one looked up, kept for good: a font registered under that name later was never used. It is now looked up for each new label, so PlayGuard can give Chinese its system font and the other languages the Latin one while it runs (`ui::use_font_for`, Preferences › Language without a restart). |
| `0014-hints-steady-on-request.patch` | The footer's hints are drawn greyed while the input is blocked, which borealis does for as long as a screen or a dialog fades in or out: they are filled again, in their usual colour, at the frame the fade ends. On the web simulator's slow frames (software WebGL, several browsers at once in CI), a screenshot taken 1.5 s after a dialog opened could still catch them greyed, so the same dialog differed from one run to the next by its hints alone. `setHintsSteady(true)` draws them as once the screen is open: greyed only for an action that is not available (`PLAYGUARD_SIM_STILL_FOCUS`, `source/ui/cadran_frame.cpp`). The input is still blocked as before. |
| `0015-view-id-readable.patch` | A view's id could be set but not read back. `View::getId()` returns it, so the screens built again for a new theme or language put the focus back on the line it was on (`source/ui/live_prefs.cpp`). |
| `0016-deko3d-command-memory-grows.patch` | On the console, nanovg's renderer gave each frame's GPU commands one fixed 128 KiB buffer and no way to get more: a frame with more draws than that holds made deko3d abort the app (Atmosphère's report: `2359-0003`, `DkResult_OutOfMemory` in `CmdBuf::requestCmdMem`, under `nvgEndFrame`). The command buffer now asks for more when it runs out, 64 KiB at a time from the renderer's data pool, given back at the start of the next frame once the GPU is done with it. |
| `0017-footer-clock-in-minutes.patch` | The footer's clock showed the seconds (`16:00:00`), changing every second at the corner of every screen for a setting counted in minutes. It now shows the hours and minutes (`16:00`), and its text changes once a minute. |
| `0018-i18n-lookups-safe-from-other-threads.patch` | With 0012, `loadTranslations(locale)` replaced the string tables on the UI thread while PlayGuard's other threads (`ui::in_background` tasks, `util/worker_threads`, the write thread) could be reading them through `getStr` / `_i18n`: a language changed in Preferences while a task built its text was a data race on the tables, a read through a table being freed. Both languages' strings are now one table, never changed once in place: a new language is loaded into a new one, put in place with an atomic `std::shared_ptr` store, and a lookup takes the table with an atomic load and holds it until it has copied its string (`getStr` returns a `std::string`), so a replaced table is freed after its last reader; loads are one at a time. Readers take no lock of their own. `tests/i18n_threads/` reads strings from four threads while the main one changes the language 300 times (under ASan and UBSan; without this patch it fails there). |
| `0019-app-locale-default-from-its-text.patch` | `Platform::APP_LOCALE_DEFAULT` (an inline variable, one for the whole program) was initialised from `LOCALE_AUTO`, a `const std::string` each file has its own copy of: with clang and libstdc++ 15 it was copied before that string was built (UBSan in `tests/i18n_threads`: a reference to a null pointer during static initialisation). It now starts from the text itself, `"auto"`. |
| `0020-hints-optional-left-out-without-room.patch` | The footer shows every key of the focused view and its parents, however many: a screen with keys of its own and the main screen's keys that work from any tab (− for the language and theme, Ⓨ for the notifications) could need more room than the footer has, its hints then drawn smaller and cut ("Zurü…", Restrictions in German with the larger text). `setHintsOptionalOwner(view)` makes that view's keys (but A and B) optional: when the hints do not all fit at their full size beside the clock, the optional ones are left out, the last one first (`source/activity/main_activity.cpp`). The header still shows the language and the bell. Without an owner nothing changes. |
| `0090-sdl-in-a-browser.patch` | The web simulator (`web/README.md`) runs on borealis' SDL platform, which asked SDL for haptic support (none in a browser) and stopped without it; it no longer asks there. The window is not resizable there either: the page scales the canvas, and borealis keeps the console's 1280×720 rather than the page's size. And `brls_web_button()`, exported to the page, presses a controller button: the page maps the keys by their meaning (X, Y, L, R… on any keyboard layout) and draws an on-screen pad, where SDL's keyboard only gives A, B and the arrows. And, a browser having no system font, borealis takes the CJK font the web build packages (`font/cjk.otf`, `tools/web_cjk_font.py`) as its fallback. All only under `__EMSCRIPTEN__`. |
