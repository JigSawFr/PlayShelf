# Code layout

Part of the [contributor's guide](../../CONTRIBUTING.md).

PlayShelf is built on the technical base of [PlayGuard](https://github.com/JigSawFr/PlayGuard). What the two apps share lives in **`source/kit/`**; what is PlayShelf's own lives beside it, in `source/`.

| Folder | What it holds |
|---|---|
| `source/kit/core/` | The C layer over libnx (platform, system information, local time, crash handler, start-up timing, the read-only switch). Each module has a plain-C header; the desktop build replaces the console's ones with `source/kit/sim/` |
| `source/kit/sim/` | The simulated console of the desktop build, driven by `PLAYSHELF_SIM_*` variables ([the simulator](simulator.md)) |
| `source/kit/util/` | Plain C++, most of it host-tested: HTTP (libcurl, TLS verified; byte ranges streamed), JSON, SHA-256, AES-128, secrets sealed for this console (`secret_box`, with `core/device_key.h`), zip, paths and atomic writes, migrations, session logs and crash reports, updates, development builds, GitHub sign-in, diagnostics |
| `source/kit/action/` | Flows: `*_logic` files are plain C++ (host-tested), `*_flow` files drive the dialogs and screens |
| `source/kit/ui/`, `source/kit/view/` | What the kit adds to the Cadran look: the app's `ui::` helpers (background tasks, the SD card's writes, `config.json`, result codes, the console's clock and system, the read-only mode, `ui::app_hooks`) and its own views (the loading screen's mark and dial, the release notes, the funding cards, a development build's cell, Made in France). Cadran itself (the frame and its rail, dialogs and pickers, lists, palettes, icons, effects, Markdown, the language and theme changed while the app runs) is [Aurore](https://github.com/JigSawFr/Aurore)'s, in `library/aurore/library/*/cadran/` ([its guide](https://github.com/JigSawFr/Aurore/blob/main/docs/cadran.md)) |
| `source/kit/activity/`, `source/kit/tab/` | The shared screens (loading, update, development builds, diagnostics, changelog, what's new) and the base of every tab |
| `source/install/` | The install formats, plain C++ with no libnx nor Aurore, host-tested and fuzzed (`tests/install/`, `tests/fuzz/install_*`): AES-128 (XTS with Nintendo's tweak, CTR, ECB), RSA-2048-PSS, the PFS0 and HFS0 archives (an NSP, a game card's partitions) and a game card's header, a title's content meta (CNMT) and the record ncm keeps of it, an NCA's header and the content meta inside a `.cnmt.nca`, and a content as it arrives (`content_stream`: a `.nca`, or a `.ncz` decompressed with zstd and encrypted again) made the bytes of its NCA, checked against the content meta's SHA-256; a package (`package`: an NSP, NSZ, XCI or XCZ, read through a `Source` of ranges) installed as one transaction (`installer`: everything checked before anything is written, every failure undone; paused and taken up again from its journal, a `.nca` where it stood) on a `Console` interface (ncm, its content meta database, ns and es); a range fetched over several connections at once and handed on in order (`split_stream`, `tests/split_stream/`); a package whose first bytes are in a file fetched ahead (`prefix_source`, `tests/prefix_source/`). The console's keys come from outside (`NcaKeys`) |
| `source/download/` | The downloads' queue, plain C++ host-tested (`tests/download_queue/`): its jobs kept in `queue.json` with each install's journal (no credential: a library server's id), a running job back as paused after a restart, the next job, the jobs by game and their timeline, the speed and the time left, the placeholders no job keeps; and what to do with a failed one (`recovery`, `tests/download_recovery/`): its cause read from its error, PlayShelf's own tries, the remedies offered, the server's other address, a package installed by now or found again in a catalogue |
| `source/library/` | The library client's formats, plain C++ host-tested and fuzzed (`tests/library/`, `tests/fuzz/library_*`): the catalogue of an AeroFoil/Ownfoil API answer (`/api/remote`, `/api/shop`), of Ownfoil 2's GraphQL API and handshake, and of a JSON index, addresses made absolute and https only, title ids and kinds, a LAN discovery answer, which of a server's addresses to use, a certificate's public-key pin; a server's catalogue fetched for a profile (`client`: the address chosen, the credentials, the API or the index, a LAN server's key pinned on first use) through a `Transport` (`http_transport`, the LAN discovery broadcast too), the profiles kept in `servers.json`, passwords sealed (`servers`), an AeroFoil server's other services (`services`, `tests/library_services/`, `tests/fuzz/library_services`: its web sign-in, its cheats and where Atmosphère reads them, a user's save backups, the games asked of it), and a catalogue gathered by game, searched and sorted (`titles`, `tests/library_titles/`); the console's games by title (`installed`, `tests/library_installed/`: a base game, its update, its add-ons); when each game was first seen on a server and the wishlist's file (`seen`, `tests/library_seen/`); how well known each game is, its trend and its critics' score (`popular`, `tests/library_popular/`), each game's traits and Steam audience and the games most like it (`signals`, `tests/library_signals/`), all read from `resources/data/`'s copies of what [PlayInsights](https://github.com/JigSawFr/PlayInsights) makes every week; the games to suggest from all those signals and the console's play, each with its reason (`recommend`, `tests/library_recommend/`) |
| `source/saves/` | A game's save as a zip archive (`archive`, plain C++ on zlib, `tests/save_archive/`, `tests/fuzz/save_archive`): made from the save's folder as it is read, read back entry by entry with each name, size and CRC-32 checked |
| `source/titledb/` | The title database, plain C++ host-tested (`tests/titledb/`, `tests/titledb_store/`): CyberFoil-DB's packs read where they lie (`CFTITLE1` names, publishers, versions; `CFICONP1` icons), its manifest (with CyberFoil's aliases, HTTPS only), a title list read as it streams and made a titles pack (Ghostland's, a Tinfoil index's `titledb` such as NXMeta's), each source's folder (packs named after their SHA-256, `state.json` written once they are checked, a cut part resumed) and the sources by priority |
| `source/core/` | PlayShelf's own C layer over libnx: `awake.h` (no automatic sleep while downloads run), `games.h` (an installed game's name, shown version and icon, from ns' control data; the room it takes and the SD card's; a game deleted), `saves.h` (the console's users, the games each has a save of, a save mounted as a folder and committed), `play.h` (how much each game was played, from pdm:qry), `install.h`, the services an install goes through (ncm's content storage and content meta database, ns's application records, es's tickets, spl's NCA keys). Switch only; the desktop build swaps in `source/sim/` |
| `source/sim/` | The desktop build's console for `source/core/`: `sim_install.cpp`, a console in `playshelf_data/sim_console/` with the host tests' keys; `sim_games.cpp`, a game's control data as files in its `control/`, a game deleted from its `meta/`; `sim_saves.cpp`, the users and their saves as folders in its `saves/`; the simulators' demo (`sim_demo.hpp`: `sim_demo_http.cpp`, the demo library server and the demo's answers of PlayInsights, Nlib API and a title database, in place of the network's on the desktop through `util/http`'s stand-in; `sim_demo_seed.cpp`, on a first start the demo's server, first games, wishlist and title database on the console); and the web simulator's own (`web_http.cpp`, the network as a console without one but for the demo's answers; `web_page.cpp`, what the page calls while PlayShelf runs) |
| `web/` | [The web simulator](../../web/README.md)'s page (its settings panel, steps, tour, service worker) and its demo, made from `tools/web_demo_games.json` (made-up games): `tools/web_demo.cpp`, its library server, PlayInsights' files and the console's first games; `tools/web_demo_art.py`, their pictures (SVG scenes of `tools/web_demo_scenes.py` rendered in Chromium), Nlib API's answers and a title database; `tools/web_smoke.py` plays it in headless Chromium, `tools/check_web_params.py` checks its settings against the simulator's variables |
| `site/`, `docs/` | [The website](../../site/README.md): its texts in each language and its styles (`site/`), the documentation it publishes (`docs/`, `docs/fr/`); `tools/build_site.py` builds it, `tools/site_screenshots.py` takes its screenshots, `tools/check_site_links.py` and `tools/site_layout.py` check it |
| `source/action/` | PlayShelf's own flows: `install_flow` (packages installed one after the other in one dialog: Help & diagnostics › developer tools › Install from a URL), `download_flow` (the downloads' queue at work: one job after the other on a worker thread, each from its journal, paused and resumed, the sigpatches checked before the first, the orphan placeholders deleted before each, the console kept awake meanwhile, a transfer cut short paused rather than undone and tried again by itself, the next packages fetched ahead when asked), `library_flow` (the Catalogue tab's servers: a catalogue fetched and kept for the run, a LAN server's key trusted on first use, the servers of this network found, a game's items added to the downloads), `installed_flow` (the Library tab's games: what is installed by game, each one's name and icon read once a run; a game deleted), `titledb_flow` (the title databases: opened at start-up, fetched again from Preferences one source after the other, the names and icons the other tabs fall back on), `library_icons` (the covers: a server's, cached, or the title database's, WebP decoded by libwebp, else Nlib API's; a game page's banner and screenshots, scaled down; every one decoded off the UI thread, the console's icons too, and shown with `aurore::Image::setImageFromRGBA`, a texture freed with its view), `nlib_flow` (a game's details from Nlib API in PlayShelf's language, kept a week; their facts kept for good in `library/facts`, gathered as the games show), `game_page` (a catalogue's game opened on its page, from the Catalogue and Home), `insights` (what Home and the bell make of the console and its servers: every catalogue read once a run, the rows, the updates to get and **Update all**), `notices` (the notification bell's entries; `notice_logic`, plain C++ host-tested in `tests/notice_logic/`: their kinds, order and those put away), `popular_flow` (PlayInsights' `popular.json`, `games.json` and `similar.json`, the ones PlayShelf came with or the newest fetched), `wishlist` (the games wished for, in `wishlist.txt`), `not_interested` (Home's suggestions put away, in `not_interested.txt`), `services_flow` (an AeroFoil server's cheats, save backups and requests, from the Catalogue's server sheet and a game's page) |
| `source/activity/`, `source/tab/`, `source/view/` | PlayShelf's screens: the main screen, the Home (where the console and its servers stand), Library (the games on the console), Catalogue (a library server's) and Downloads tabs, a library server's editor (`server_activity`), a game's page (`game_activity`: its lines, and what Nlib API knows of it), the notification bell (`notice_bell`) and its list (`notices_activity`, its entries from `insight_notices`), the SD card's room (`storage_activity`), the search of every server (`search_activity`), a game's cover (`game_tile`), line (`game_cell`) and wide banner (`banner_card`), a tab's control as a pill (`tool_chip`), a game's packages in the downloads as one line (`timeline`) |
| `source/` (outside `kit/`) | PlayShelf itself: `main.cpp`, `app.*` (its identity and modes), `util/config.*` (its settings), its screens and tabs |

The rules `tools/check_sources.py` enforces:

- **The kit includes nothing of the app** but `app.hpp` and `util/config.hpp` (the app's identity and settings). It asks anything else of the app through Aurore's `ui::hooks` (`aurore/cadran/ui/hooks.hpp`: the main screen, the tabs' positions and rail icons, PlayShelf's version, logo and read-only mode, saving the look's preferences) and the kit's own `ui::app_hooks` (`source/kit/ui/app_hooks.hpp`: the notifications, a check before PlayShelf replaces itself), which `source/activity/screen_hooks.cpp` fills in at start-up. The kit can then become a library shared with PlayGuard without untangling anything.
- `ui/`, `view/` and `util/` never include `activity/` or `tab/`; a flow includes only the screens it opens itself.
- A C file of `source/kit/core/` that needs no console service is in the desktop build and in a host test.

The Cadran look: a colour is always a palette key (`cadran::kit::color("cadran/teal")`, `@theme/cadran/...` in XML), never a literal; Aurore's tests check every ink on every surface in both themes.
